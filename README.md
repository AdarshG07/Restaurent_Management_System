# Restaurant Management System

A full-stack restaurant management application built with React, Vite, Tailwind CSS, Node.js, Express, MongoDB, Socket.IO, and Razorpay.

## Project Structure

- `client/` — React frontend built with Vite, Tailwind CSS, and Socket.IO client.
- `server/` — Express backend with MongoDB, authentication, payment integration, reporting, and real-time admin notifications.

## Features

### Customer Experience
- Welcome and digital menu browsing with search, categories, availability, and veg/non-veg filtering.
- Detailed menu pages, favorites, and item quick-add functionality.
- Persistent cart with quantity, instructions, and discount support.
- Checkout flow that creates orders, launches Razorpay checkout, and verifies payment signatures.
- Order tracking with live status updates via Socket.IO.
- Receipt viewing, PDF generation, and print-ready receipt support.
- Feedback submission for completed orders.
- Table selection via QR codes generated by the admin panel.

### Admin Experience
- Secure admin login and protected admin routes.
- Dashboard with order, menu, category, table, billing, report, and review management.
- Kitchen view with order status workflow: RECEIVED → PREPARING → READY_TO_SERVE → SERVED.
- Menu item management including stock quantity, availability, special/recommended flags, and low-stock notifications.
- Category CRUD and manual order creation.
- Table management with QR code links to the customer menu page.
- Custom billing creation and billing history.
- Review listing and moderation.
- Real-time admin notifications for new orders, payments, and low-stock alerts.

### Backend and Infrastructure
- Express REST API with Mongoose models for users, tables, categories, menu items, orders, payments, reviews, billing, reports, and notifications.
- JWT-based admin authentication.
- Socket.IO for live admin notifications and order tracking.
- Razorpay integration for payment order creation and signature verification.
- CORS support configured via `CLIENT_URL`.
- Production-ready static front-end serving when `NODE_ENV=production`.

## Environment Variables

### Server
Create a `.env` file in `server/` with:

```env
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/<dbname>?retryWrites=true&w=majority
JWT_SECRET=your_jwt_secret_here
CLIENT_URL=https://your-frontend-url
RAZORPAY_KEY_ID=rzp_test_example
RAZORPAY_KEY_SECRET=your_razorpay_secret
PORT=5000
NODE_ENV=development
```

### Client
Create a `.env` file in `client/` with:

```env
VITE_API_BASE_URL=https://your-backend-url/api
VITE_RAZORPAY_KEY_ID=rzp_test_example
VITE_FRONTEND_URL=https://your-frontend-url
```

## Deployment Readiness

- Frontend deployment should use `VITE_API_BASE_URL=https://<your-backend-url>/api` and `VITE_FRONTEND_URL=https://<your-frontend-url>`.
- Backend deployment should use `PORT`, `MONGODB_URI`, `JWT_SECRET`, `CLIENT_URL`, `RAZORPAY_KEY_ID`, and `RAZORPAY_KEY_SECRET`.
- `CLIENT_URL` is used by backend CORS and Socket.IO.
- `VITE_API_BASE_URL` is used by the frontend to call the backend API.
- `VITE_RAZORPAY_KEY_ID` is the only Razorpay key exposed to the browser; `RAZORPAY_KEY_SECRET` remains backend-only.
- If deploying the frontend separately to Vercel, ensure your production build handles SPA routing with a fallback to `index.html`.
- If deploying the backend to Render, use `npm start` and set `PORT` from the environment.

## API Endpoints

### Authentication
- `POST /api/auth/login` — admin login.
- `GET /api/auth/profile` — get authenticated admin profile.

### Tables
- `GET /api/tables` — list tables.
- `POST /api/tables` — create a table.
- `DELETE /api/tables/:id` — delete a table.
- `PATCH /api/tables/:id/status` — update table status.

### Categories
- `GET /api/categories` — list categories.
- `POST /api/categories` — create category.
- `PUT /api/categories/:id` — update category.
- `DELETE /api/categories/:id` — delete category.

### Menu
- `GET /api/menu` — list food items with filters.
- `GET /api/menu/:id` — get food item details.
- `POST /api/menu` — create food item.
- `PUT /api/menu/:id` — update food item.
- `DELETE /api/menu/:id` — delete food item.

### Orders
- `GET /api/orders` — list orders.
- `GET /api/orders/:id` — get order detail.
- `POST /api/orders` — create a customer order.
- `POST /api/orders/manual` — create an admin manual order.
- `PATCH /api/orders/:id/status` — update order status.

### Payments
- `POST /api/payments/create` — create Razorpay payment order.
- `POST /api/payments/verify` — verify Razorpay payment.
- `GET /api/payments/:orderId` — get payment status.

### Reviews
- `POST /api/reviews` — submit customer review.
- `GET /api/reviews` — list reviews.

### Billing
- `POST /api/billing` — create custom bill.
- `GET /api/billing` — list bills.
- `GET /api/billing/:id` — get bill detail.

### Reports
- `GET /api/reports` — get report data.

### Notifications
- `GET /api/notifications` — list admin notifications.
- `PATCH /api/notifications/:id/read` — mark notification read.

## Real-time and Payments

- Socket.IO is used for admin notifications and live order updates.
- Admin sockets join the `joinAdmin` channel and receive `notification` events.
- Customer order tracking joins the `joinTable` channel and receives `orderUpdate` events.
- Razorpay is used on checkout to create payment orders and verify signatures.
- `LOW_STOCK_THRESHOLD` is set to `5` and low stock alerts are emitted when stock quantity falls below or equal to that threshold.

## Notes

- The admin UI is protected by JWT and requires login before accessing `/admin/*` routes.
- The customer menu supports veg/non-veg filtering via `isVeg`.
- Table QR codes point to `/menu?table=<number>`.
- The app is built for local development with separate client and server processes.
